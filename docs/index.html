Why ermod-engine

Your game install is never touched.
The engine reads the game directory and writes nothing into it, so Steam's integrity check has nothing to revert. Your own regulation.bin is never overwritten.
Your saves are never touched.
Modded play happens on a profile, a copy of your save kept in the engine's own directory. It copies your characters in by reading your save, never by writing it. The one command that writes your save runs only when you ask, and backs it up first. More on profiles.
Co-op over LAN or VPN, private by default.
Up to five players, peer to peer, on your home network or over ZeroTier or Tailscale. There is no matchmaking and no FromSoftware server: only machines you can reach can join you, and you can only join machines you can reach. No strangers dropping in, and no lobby password to share. Want a say anyway? One setting makes the host approve each join. Setting up LAN or VPN.
Mods are live Lua scripts.
Switch any mod on or off from the in-game menu, no restart. Edit a file while you play and it reloads within a second. Each mod runs in its own sandbox with only the modules it declares; one that misbehaves is switched off and the others carry on.
Mods follow the host, with your consent.
When the host plays with mods that change the game, every player needs them. Join without them and the menu lists the host's mods, already downloaded, each with an Enable button. Nothing is written to your mods directory until you press it. Mods that only draw or log can differ. Mods in co-op.
Native on Linux and macOS.
A native launcher for Linux x86-64 and Apple Silicon. It finds your game and drives Proton, CrossOver, Whisky or protium for you. No Windows machine, no setup.
Small and quick.
One download of a few megabytes, and nothing to install: unpack it and play.

What else it does

The game's live parameter tables, readable and writable: the same data a regulation.bin holds, edited in the running game. Mods can also draw an in-game overlay, report frame timing, and keep their own settings between sessions.

A modded regulation.bin without ModEngine. Point the engine at one and the game reads it instead of its own file.

Safe by design. Modded play means anti-cheat is off, so Easy Anti-Cheat never runs and modded sessions never reach FromSoftware's servers. The one launch that does risk a ban is the game's normal Steam launch with a modified regulation.bin in place. The install guide has the rules; they are not fine print.

On Linux it runs the game under Proton; on macOS, inside a Wine bottle. Either way it launches eldenring.exe directly and never the anti-cheat wrapper, and refuses to run at all while Easy Anti-Cheat is live.

A mod is one file

This one starts the Vagabond at level 60. Drop it in the mods directory; it loads on the next frame. 

local mod = {
  name = "level60",
  version = "1.0.0",
  run_at = "launch",
  permissions = { "params", "log" },
}

function mod.on_launch(sdk)
  local row = sdk.params.row("CharaInitParam", 3000)
  row.soulLv = 60
end

return mod

permissions is the whole of what a mod can reach: a module not listed is absent from the sdk table it receives, so it cannot be called rather than merely refused. Eleven worked examples and the full reference are in the scripting guide.

Checking the download is ours

Every release is signed. The signature covers SHA256SUMS, which pins each archive by hash, and travels as a Sigstore bundle alongside it. 

cosign verify-blob SHA256SUMS \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity 18033717+Benehiko@users.noreply.github.com \
  --certificate-oidc-issuer https://github.com/login/oauth

sha256sum --ignore-missing -c SHA256SUMS        # macOS: shasum -a 256 --ignore-missing -c SHA256SUMS

Signature first, then checksums: checksums from the same page as the archive only prove the two agree, not that either came from us. On macOS, Gatekeeper refuses the first run of a browser download; the install guide says how to clear it.

Signing is keyless, so there is no private key to leak: the certificate records the identity that signed and is logged publicly in Sigstore's transparency log.

When the game updates

The engine is keyed to exact game builds. On one it does not recognise it says so, disables every hook and lets the vanilla game run. It never guesses. ermod-engine check-build answers why, and a newer release is the fix.

The engine is closed source; this repository publishes the SDK stubs, the examples and the param definitions a mod is written against. Not affiliated with FromSoftware or Bandai Namco.
